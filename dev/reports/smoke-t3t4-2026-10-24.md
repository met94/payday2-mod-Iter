### Big Bank — crash on `!iter probe 20`

Crash stack:

```
itr_get_closest_door_to_pos() @mods/Iter/lua/navigationmanager.lua:828
@mods/Iter/lua/navigationmanager.lua:1062
probe() @mods/test-harness/lua/chatmanager.lua
```

Line 828 is the Vector3 branch of the door picker. `i_door.x` was truthy on a
non-Vector3 userdata (a nav-link object), then `mvector3.distance(i_door, pos_to)`
passed that userdata to the engine and caused an access violation.

Fix in the next build:

- `is_vec3(value)` requires `type(value) == 'userdata'` and numeric `x/y/z`.
- Every door branch uses it before vector math.
- `pos_to`/`pos_from`/`near_pos` are validated; a bad value increments
  `door_bad_pos_to` and returns instead of crashing.

## Big Bank probe verification (build 6adb2d3)

No crash. `!iter probe 30`:

```
pairs=29 search(ok=29 fail=0) streamline(ok=5 fail=24)
evt=probe pairs=29 search_ok=29 search_fail=0 stream_ok=5 stream_fail=24
door_bad_pos_to=24
```

The crash guard worked; the 24 streamline failures were a **probe bug**, not a
mod bug: with `nav_search=true`, `search_coarse` already returns a
streamlined path (positionless duplicate final step), and the probe then
called `itr_streamline` a second time. The second pass had no final position,
so the new vector guard returned nil (`door_bad_pos_to`).

Fix: `itr_streamline` is now idempotent — a path whose final step has no
Vector3 position is returned unchanged (`streamline_skip_done` counter).

Search itself: 29/29 successful on Big Bank. `!iter ai`: 8 cops, 6
travelling, 6 coarse paths, 6 direct-to-pos.
