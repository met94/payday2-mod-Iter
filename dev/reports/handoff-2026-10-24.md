# Handoff — build cc3f161 (combined T3 + T4)

## Why this build

The first T3 run produced no Iter errors and good nav data. The card failed
only because the harness AI diagnostic read the wrong enemy table and the
build had no heartbeat when quitting to desktop. Both are fixed, plus search
counters and cache invalidation. This build combines T3 (AI + nav links) and
T4 (Iter search + direct-to-pos) into one session.

## Run (three heists, ~20 min)

1. **Hotline Miami D1**: wait 35 s, `!iter alarm`, wait 60 s,
   `!iter links`, `!iter ai`, `!iter path`, quit to menu.
2. **Jewelry Store** (stealth): wait 35 s, `!iter ai`, `!iter path`,
   `!iter dump`, quit to menu. This is the direct-to-pos check.
3. **Big Bank**: `!iter probe 20`, wait 35 s, `!iter ai`, quit and send the log.

Wait at least 35 s in each heist so the heartbeat fires.

## Expected

- `evt=boot` shows `navlink_queue=true path_extender=true nav_search=true
  direct_to_pos=true nav_ai=true`.
- `evt=navlink elements=...` and `evt=summary ... navlink_prepare>0` every 30 s.
- T3: `navlink_prepare > 0`; queue may still be 0 if no ladder is used.
- T4: `summary.search_ok > 0` after the probe; `summary.direct_to_pos > 0`
  from the Jewelry stealth run.
- No `[ITER-ERR]`, no fallback, no FATAL.

If pathing visibly breaks: turn **AI cluster**, **nav-link queue**, and
**path extender** OFF, keep overlay+streamline+search, run Hotline once, send
both logs.

Scan: `T3-navlink.json` and `T4-search.json` against the same log.
